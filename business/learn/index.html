Mentor · Prototype preview

How a learning plan takes shape

A mentor describes a task and reviews the steps before a trainee sees them.

Read preview: How a learning plan takes shape
  1. In the private prototype, the mentor describes a task and the support it needs.
  2. An invented example might be arranging three paper cups. The draft describes steps and observable demonstration criteria.
  3. The mentor checks and approves the content before it becomes part of the trainee’s plan. The current test version uses scripted drafting, not a live AI service.
Trainee · Prototype preview

How a trainee finds a next step

A trainee sees a mentor-approved focus and practises with support.

Read preview: How a trainee finds a next step
  1. The trainee view presents a focus approved by the mentor and the steps for each skill.
  2. Practice can happen with support before an independent demonstration.
  3. A trainee can request a review. That request does not change the mark automatically; the mentor decides.
Everyone · Prototype preview

How note sharing works

The prototype distinguishes private reflections from deliberately shared notes.

Read preview: How note sharing works
  1. New reflections in the prototype start private to the author within the app.
  2. Sharing gives the assigned learning partner access to a saved note.
  3. Stopping sharing removes access on the next request; it cannot recall a copy already displayed. System operators can access stored data.
  4. These are prototype behaviors, not a certification or a promise of production security.
Mentor · Prototype preview

How a learning request is reviewed

The mentor considers a request before deciding whether a mark changes.

Read preview: How a learning request is reviewed
  1. The mentor’s review screen presents pending requests and suggestions.
  2. The mentor considers the relevant skill and decides whether to approve or decline.
  3. Neither the guided tour nor an AI suggestion approves a change on the mentor’s behalf.
Everyone · Prototype preview

How messages and resources work

Sending is deliberate, and outside resources show their destination first.

Read preview: How messages and resources work
  1. Inbox holds questions and replies between the assigned learning pair. Typing alone does not send a message.
  2. Outside resources first display their destination and a choice to cancel or continue.
  3. Continuing opens a separate tab, preserving the KMB tab.
Manager · Prototype preview

What a manager can see

The manager view presents the training outline within a limited role.

Read preview: What a manager can see
  1. The manager view presents the training outline.
  2. This app role does not display learner notes, conversations or individual marks.
  3. An app role is distinct from direct server access; the prototype does not claim that system operators cannot access stored data.

Questions & answers

A clear answer.
A useful next step.

Starter questions for the prototype—not questions collected from real users.

Can I use KMB today?

KMB is a private working prototype, not a publicly available app. This page explains the idea. Contact Joseph to discuss it; no public sign-up, download or access is promised.

Has this been validated in a workplace?

No completed pilot validation is being claimed. Testing so far uses invented people and information. Real workplace testing needs agreed safeguards, permissions and approvals.

Does AI approve a learning plan?

No. The mentor reviews and approves suggestions. The current test version uses scripted drafting; it does not demonstrate a live AI service.

How does the prototype handle outside resources?

In the prototype, a confirmation shows the destination before a resource opens in a separate tab. The original KMB tab stays available.
